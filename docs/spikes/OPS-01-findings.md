## 3. Restart / recovery

`ops/scratch/restart-recovery.json`.

- `docker kill` (SIGKILL) langfuse-web + langfuse-worker → **`restart: always`
  did NOT auto-recover them**: both stayed `Exited (137)` for 2+ minutes with no
  restart attempts, even with all dependencies healthy. Recorded honestly as a
  finding; `restart: always` remains in compose (compose-spec intent) but the
  runbook does not rely on it.
- Proven recovery: `docker compose -p oaa-ref --env-file .env up -d --wait` →
  healthy in **19 s**; post-recovery trace readback 200 and receipt still
  readable.
- Pitfall found: running `docker compose up` in the install dir *without*
  `-p oaa-ref` created a duplicate `oaa-reference-stack-*` container set that
  collided on ports; removed via `docker compose -p oaa-reference-stack down -v`.
  Runbook now mandates the explicit project name.

## 5. Load smoke (bounded, local stack only)

`ops/scratch/load-report.json` — `tests/load/load_smoke.py` (based on
reference_agent span shapes; `--rate 10 --duration 120 --baseline-duration 30`):

| Metric | Value |
|---|---|
| measured runs / spans | 1,201 runs × 20 spans (≈24,020 spans emitted) |
| baseline runs / spans | 300 × 20 (no-export, InMemory sink) |
| p50 per-run producer wall-clock | 1.55 ms (measured) vs 2.95 ms (baseline) |
| p95 per-run producer wall-clock | 3.58 ms (measured) vs 5.57 ms (baseline) |
| p95 overhead vs no-export | **−2.0 ms (ratio 0.64)** — i.e. batching export adds no measurable producer-side p95 cost at this rate |
| Ingestion check | 1201 new traces visible through the legacy read API after flush (total 1202 incl. proof trace) |

This is a smoke, not a benchmark: single host, one exporter, batch size 512.
The negative overhead is noise — the claim is only "no producer-side p95
degradation ≥ 1 ms at 10 runs/s after a 2-min steady window."

## 6. Known gaps / deferred (per plan §15)

- **k8s deployment deferred**: this package is docker-compose only; no
  Helm/manifest, no multi-node storage (ClickHouse/Postgres HA, PVC sizing,
  resource planning, storage-growth model) — TODO per plan section 15.
- restart:always not relied upon (see §3); a real supervisor/daemon-level
  restart policy (e.g. `docker compose restart` automation or restart-priority
  ordering) is untested beyond the compose up path.
- Backup consistency: proven for a stopped stack; hot (running) backup is
  documented as "stop or pause writes first" — crash-consistent live backup is
  untested.
- ClickHouse data tgz is 130 MB for ~24k spans: retention/compaction tuning and
  growth modelling not yet done.
- evidence-index stub is single-instance, no auth; replace with the planned
  evidence-index service (services/evidence-index/README.md) before multi-agent use.
- Load smoke doesn't exercise the redaction processor path (collector absent by design).
